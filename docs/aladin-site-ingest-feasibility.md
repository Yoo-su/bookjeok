# 알라딘 웹·YES24 신규 도서 적재 조사와 개편

조사일: 2026-11-01. API 공급처를 교체하기 위한 사전 조사이며, 운영 DB·R2에 쓰지 않았습니다.

## 구현 결과 (2026-11-01 후속)

`tools/book-ingest`를 합의한 방식으로 개편했습니다. 카카오에서 출판사·ISBN 후보를 찾고
보유 도서를 제외한 뒤 선택 도서만 알라딘 웹 + YES24 두께로 보강합니다. 기본 최근 90일·
출판사별 2페이지·전체 신규 후보 30권, 한 번에 최대 100권입니다. 성공한 웹 응답은 24시간
캐시하고 필수값 누락은 캐시·저장하지 않습니다. 실패한 책 선택과 중단한 실행의 실패·미처리
책 복원 명령을 추가했습니다. 기존 API 호출은 제거했습니다.

- 실제 5권(민음사·문학동네·노란상상)에서 서지·소개 전문·판형·YES24 두께·500px 표지·표지색을 확인했습니다.
- 민음사 최근 후보를 검색하고 DB를 READ ONLY로 대조해 신규 2권·보유 3권·제외 45건을 확인했습니다. 신규 2권 『강남 스토리』·『손실 압축 알고리즘』도 `inspect`로 전 필드를 확보했습니다.
- 처음 `inspect`는 권당 약 7.5~9.4초, 같은 책의 캐시 재확인은 약 0.45초였습니다. R2·DB 쓰기 시간은 포함하지 않습니다. 아래 초기 조사의 1.44초는 대기·표지 처리가 없는 HTTP 응답 합계이므로 구분해야 합니다.
- 리뷰에서 부제 누락·불완전 상세 캐시·재사용 표지 폭 미검사·기록 파일명 충돌을 보완했습니다. 부제는 보존하고 시리즈 링크는 제외하며, 기존 R2 표지도 500px 미달이면 덮어쓰기 없이 실패합니다.
- 운영 INSERT·R2 업로드·DDL은 실행하지 않았습니다. 사용법과 세부 동작은 [적재 도구 README](../tools/book-ingest/README.md)가 현재 기준입니다.
- 최종 타입 검사·린트·단일 워커 테스트 142개가 통과했습니다. 실행 환경은 로컬 Node 24.17.0이며 프로젝트 권장 버전은 22입니다.

이하 「판단」·「개편 전 적재 계약」은 조사 과정의 근거입니다. 수집·저장 조건에 관한
조사와 전체 도서 커버리지는 구현 검증과 구분합니다.

**사용자 요구조건(후속 확인): 기존에 적재하던 모든 필드를 빠짐없이 확보해야 한다.**
NULL·기본값·쪽수 기반 두께 추정으로 누락을 덮는 안은 이번 개편의 충족안에서 제외한다.
아래의 부분 정보 적재·기존 서버 추정 설명은 현 시스템 동작에 대한 참고이며 채택안이 아니다.
필드가 존재하는 것과 공급처 간 값이 일치하는 것은 별도로 검증한다.

**공급처 분담 확정(2026-11-01, 사용자 결정): 두께는 동일 ISBN의 YES24 값을 사용한다.**
표지·서지·정가·판매지수·긴 소개·폭·높이·쪽수·무게·제본은 알라딘 웹에서 받고,
YES24에서는 두께만 받는다. 두께가 기존 알라딘 API 값과 달라도 YES24 값을 채택하며,
이 차이 자체를 개편의 보류 사유로 두지 않는다. YES24에 두께가 없거나 ISBN·종이책
판본이 일치하지 않으면 추정값으로 채우지 않고 미확보로 처리한다.
기존 DB 행을 YES24 두께로 일괄 변경하는 결정은 아니다.

## 판단

**공개 상품 페이지에서 기존 적재 필드 대부분을 얻는 것은 기술적으로 가능하다. 다만 알라딘 사이트 단독으로 실측 두께까지 계속 확보할 수 있다는 근거는 없으며, 기존과 동일한 데이터·무중단 수집을 보장할 단계는 아니다.**

- 현재 HTTP 응답으로 `cover500` 표지, ISBN·제목·저자·출판사·출간일·정가·판매지수, 폭·높이·쪽수·무게·일부 제본, 출판사 소개 전문을 확인했다.
- **두께는 직접 확인한 종이책 4권 모두 기본정보에 없었다.** HTML에서 API의 `sizeDepth` 같은 값도 발견하지 못했다. 다른 공개 화면·응답 어디에도 없다는 전수 결론은 아니다.
- 같은 ISBN 3권의 YES24 품목정보에는 두께가 있다. **알라딘 웹 + YES24 두께 조합으로 개편 방향을 확정했다.** 전체 신간의 필드 확보율과 수집·저장 조건은 별도 확인 항목이다.
- 알라딘 `robots.txt`의 일반 봇 규칙은 전면 차단이다. 공개 페이지를 읽을 수 있다는 사실만으로 북적의 반복 수집·R2 재게시가 허용됐다고 판단하지 않는다.
- **초기 조사 시점에는 적재 코드를 변경하지 않았다.** 이후 구현·검증 결과는 위 절에 기록했다. 환경 변수·운영 데이터는 변경하지 않았다.

## 개편 전 적재 계약과 교체 범위

문서 설명에만 의존하지 않고 아래 코드를 확인했다.

- 구 `src/sources/aladin.ts`(이번 개편에서 제거): 검색·목록 및 `ItemLookUp` 보강. 소개 우선순위는 `fullDescription2 → fullDescription → description`, 판형은 `subInfo.packing`, 정가는 `priceStandard`였다.
- [`db.ts`](../tools/book-ingest/src/db.ts): `books`에는 ISBN·제목·저자·출판사·정가(`discount`)·출간일·소개·자사 표지 URL·판매지수, `book_dimensions`에는 폭·높이·두께·쪽수·무게·제본·표지색을 넣는다. API의 카테고리·상품 링크·판매 상태 등은 선별·화면·실행 기록에도 쓰이므로 공급처 교체 때 함께 매핑해야 한다.
- [`ingest.ts`](../tools/book-ingest/src/ingest.ts): 보강 → 표지 가공 → R2 업로드·공개 URL 확인 → 표지색 → 두 테이블의 단일 트랜잭션 INSERT. 이 흐름과 표지색 추출은 재사용할 수 있다. 추정 크기는 저장하지 않는다.
- [`sources/types.ts`](../tools/book-ingest/src/sources/types.ts): `BookSource`의 검색·정제·보강 계약 뒤에 새 공급처를 둘 수 있다. 기존 계약은 API 키가 필요한 공급처와 전체 공급처의 `lookupDimensions` 대여를 전제하므로 웹 보강·수동 파일 공급을 지원하려면 등록·활성화 조건도 조정해야 한다.
- [`runtime.ts`](../tools/book-ingest/src/runtime.ts), [`sources/index.ts`](../tools/book-ingest/src/sources/index.ts): **현재도 알라딘 키가 있으면 카카오 적재까지 알라딘 판형 조회를 호출한다.** 조회 실패를 잡아서 생략하지 않으므로 종료된 API 키가 남은 환경에서 카카오로 바꾸기만 해도 적재가 실패할 수 있다. 실제 운영 적재 실패를 재현한 것은 아니며 코드 경로에서 확인한 영향이다.

| 기존 저장값 | 사이트에서의 확보 가능성 | 현재 확인 범위 / 주의점 |
| --- | --- | --- |

### 상품 식별과 표지

- 마지막 표본은 [`wproduct.aspx?ISBN=9791124269800`](https://www.aladin.co.kr/shop/wproduct.aspx?ISBN=9791124269800)으로 HTTP 200을 받았고, 응답 canonical과 JSON-LD의 상품명·ISBN이 위 상품과 일치했다. **이미 알고 있는 ISBN으로 상품을 찾는 경로 1건**을 확인한 것이며, 출판사별 신간 발견·베스트셀러 페이지네이션은 실측하지 않았다.
- 『압구정 현대를 사지 못해서』 HTML이 명시한 [앞표지 파일](https://image.aladin.co.kr/product/40350/74/cover500/8937449676_1.jpg)을 내려받아 실제 500×759px JPEG임을 확인했다. 기존 도구가 적재한 500px 등급과 같다. URL을 추측해 확장하거나 더 큰 원본을 확보했다는 뜻은 아니다.
- 이미지 경로에는 ISBN-10뿐 아니라 `k592131828` 같은 내부 코드도 들어간다. ISBN으로 CDN 경로를 조합하지 말고 상품 페이지가 명시한 주소를 사용해야 한다.
- 『압구정…』의 공개 [책등 받기](https://www.aladin.co.kr/shop/book/wbookspine_down.aspx?itemid=403507480)는 93×1000px JPEG를 반환했다. **이미지 픽셀 비율은 실측 두께 필드가 아니다.** DPI나 비율로 계산한 값을 `depth` 실측값으로 넣으면 안 된다. 4권의 HTML에서 발견한 3D 표시용 CSS도 실측 두께 근거가 되지 못했다.

### 책소개 전문

상품 본체 HTML에는 소개 컨테이너만 있고, [`jquery.lazyload.js`](https://www.aladin.co.kr/js/jquery.lazyload.js?v=20151110)의 `loadContent`가 `/shop/product/getContents.aspx`를 호출한다. `PublisherDesc`·`Introduce` 등을 별도로 불러오는 구조다.

- 단순 GET으로는 HTTP 200에 빈 본문이 왔다. 페이지 스크립트의 요청 형식에 맞춰 `ISBN`·`name=PublisherDesc`·`type=0`·`date` 쿼리, 해당 상품의 Referer 및 `X-Requested-With: XMLHttpRequest`를 보낸 요청에서는 본문이 왔다. **어느 요소가 필요조건인지 각각 분리 실험하지는 않았다.**
- 『압구정…』은 응답 11,696 bytes, 태그·스크립트 제거 후 공백을 정리한 텍스트 약 2,894자, 『일곱개의 이름』은 22,851 bytes / 약 7,265자였다. 두 응답에서 출판사 소개 표제·해당 도서명을 확인했다. 소개 전문을 이 문서에 복제하지 않는다.
- 이 경로는 공개 웹 화면의 부가 응답이며, 종료된 Open API의 공식 대체 계약이 아니다. HTML 구조·요청 조건 변경, 상품별 결측에 대비해야 한다.

### 기존 API 저장 원본과의 추가 대조

로컬 실행 기록 `tools/book-ingest/.data/runs/20261005T131924-apply.jsonl`에
ISBN 9788937449673의 실제 적재 원본이 남아 있었다. 자격증명·전체 원문은 문서로 옮기지 않았다.

- 당시 `packing`은 **135×205×23mm · 416쪽 · 541g · 반양장본**이었다. YES24의 30mm와 두께까지 다르다. 어느 공급처가 실제 책과 맞는지는 이번 조사로 판단하지 못했지만, **사용자가 차이를 수용하고 신규 적재에는 YES24 두께를 쓰기로 결정했다.** 기존 적재값은 변경하지 않는다.
- 당시 API `fullDescription2`는 HTML 포함 2,316자였다. 태그 제거·엔티티 디코딩·공백 통일 후 본문이 현재 알라딘 `PublisherDesc` 응답 안에 포함됨을 확인했다. 현재 응답의 표제·버튼 등까지 저장하면 내용이 달라지므로 본문 영역을 추출해야 한다. 이 비교는 1권이며 전 상품의 동일성을 증명하지 않는다.
- 같은 도서의 공개 모바일 URL은 이번 직접 요청에서 PC canonical을 가진 동일 계열 HTML을 반환했고 추가 두께를 발견하지 못했다. 상품 페이지가 쓰는 `InfoNotification3` 응답도 반품·교환 안내였으며 판형을 주지 않았다. 다른 공개 경로가 모두 배제됐다는 결론은 아니다.
- YES24가 공개 페이지에 명시한 [메인 표지 XL](https://image.yes24.com/goods/197318629/XL)은 직접 다운로드해 **790×1200px**임을 확인했다. 대체 공급처의 표지 접근 가능성에 대한 1장 표본이며 전체 도서 해상도 보장은 아니다.
- YES24 『일곱개의 이름』의 웹 도구 반환 본문에서는 제본 표기를 찾지 못했다. 알라딘 고유 판매지수도 YES24가 줄 수 없으므로 한 공급처에서 기존 전 필드를 빠짐없이 얻었다는 검증은 아직 없다.

출판유통통합전산망 [공식 사용자 매뉴얼](https://bnk.kpipa.or.kr/files/board/00000000000000000100/2024/02/23/20240223110551-1818381264186285364.pdf)은 API 신청 화면과 JSON/XML·도서상세 개발문서 다운로드를 안내한다. 그러나 이번 공개 조사에서 실제 응답 명세를 확보하지 못했다. 등록항목에 두께가 필수라는 사실만으로 실제 API에서 두께·무게·긴 소개·원본 표지를 모두 준다고 확정하지 않는다.

협의형 후보로는 [출판유통통합전산망 Open API](https://bnk.kpipa.or.kr/home/v3/center/centerGuideOpenApi)가 있다. 공식 안내는 출판사 동의 도서 제공 및 신청·심사를 전제로 한다. [메타데이터 관리항목 별표2](https://bnk.kpipa.or.kr/home/v3/center/centerGuideUseTerms)에 종이책 가로·세로·페이지·두께·표지가 필수 등록항목으로 명시돼 있으나, **API가 실제로 해당 필드를 제공하는지·신간 커버리지·표지 해상도는 미검증**이다. API 약관 제8조⑤의 독립 노출·출처 표시 조건도 북적의 통합 DB 적재와 맞는지 협의해야 한다. 기존 계획서 6장의 국립중앙도서관 검토를 뒤집는 제안은 아니다.

## 개편 방향과 다음 검증

### 소규모 출판사 선택과 속도

사용자가 기존처럼 원하는 출판사를 골라 소규모로 적재하는 운영 방식을 요청했다.
초기 개편 범위는 출판사 선택 → 후보 검색 → DB 보유 ISBN 제외 → 운영자가 고른 책만
알라딘 웹·YES24에서 보강 → 전체 필드 검사 → 기존 저장 파이프라인이다.
출간 기간·후보 페이지·적재 권수에 명시적인 한도를 두고, 예를 들어 최근 3개월의
신간 중 30권을 고를 수 있게 한다. 이 숫자는 제안 예시이며 확정 제한이 아니다.
과거 베스트셀러 전량 수집은 초기 개편 범위에 넣지 않는다.

현재 `scan.ts`는 이미 DB 보유 ISBN을 거르고 `workflow.ts`는 책별 순차 적재·성공/실패
기록을 남긴다. 기존 `.data/list-cache`는 과거 API 목록만 캐시하므로 웹 상세·두께의
지속 캐시는 새로 필요하다. 보강 응답의 ISBN·수집 시각·출처를 함께 보관하고 실패한
책만 재시도할 수 있게 한다. DB 보유 책에 불필요한 상세 조회를 하지 않는 것이
소규모 반복 운영의 주된 절감 수단이다. 이미 보유한 페이지를 만났다는 이유만으로
목록 전체를 끝내지는 않는다(과거 누락분 존재); 운영자가 지정한 범위로 제한한다.

**직접 HTTP 단발 측정(2026-11-01, ISBN 9788937449673):**

| 요청 | 응답 시간 |
| --- | ---: |
| 알라딘 ISBN 상품 상세 | 0.547초 |
| 알라딘 출판사 소개 AJAX | 0.089초 |
| YES24 ISBN 검색 | 0.420초 |
| YES24 상품 상세 | 0.381초 |
| 합계 | 약 1.44초 |

YES24 ISBN 검색 결과가 상품 197318629로 연결됐고, 상세 원문의 ISBN13과
135×205×30mm 규격을 확인했다. 소개도 빈 응답이 아닌 11,696 bytes였다.
**이는 1권의 네트워크 응답 시간 합계일 뿐 처리량 벤치마크가 아니다.** 표지 다운로드·가공,
R2 업로드·검증, DB 저장, 호스트별 요청 간 대기, 재시도는 포함하지 않았다.
수십 권을 분 단위로 처리하는 것을 목표로 하되 실제 배치 소요 시간은 구현 후 측정한다.

1. **공급처 교체 지점은 운영자 적재 도구에 둔다.** 카카오 검색/운영자 ISBN 선택으로 후보를 찾고, 알라딘 웹에서 기존 필드를 확보한 뒤 동일 ISBN의 YES24 두께를 결합한다. 서버 런타임에는 외부 공급처를 다시 넣지 않는다. 알라딘 출판사 검색·과거 베스트셀러 모드를 동일 기능으로 보존할지는 별도 범위다.
2. **기존 필드 완전성을 적재 조건으로 둔다.** 현 계정은 INSERT만 가능하고 `ON CONFLICT DO NOTHING`이라 이미 생긴 판형 행의 NULL 두께를 나중에 채울 수 없다. 미확보 책은 적재 성공으로 처리하지 않고 검수 대기로 남겨야 한다. 이 정책만으로 모든 신간 확보 문제가 해결되는 것은 아니므로, 공급처별 실제 확보율을 먼저 검증한다.
3. **현 서버의 추정은 요구 충족안에서 제외한다.** [`estimateBookSize`](../packages/core/src/features/reading-log/utils.ts)는 쪽수·제본으로 두께를 추정하고, 3축 중 하나라도 보충하면 `sizeSource=estimated`로 반환한다. 이는 현 동작 설명일 뿐 이번 개편에서 누락을 대신할 방안으로 채택하지 않는다.
4. **운영 채택 전에 확인할 것:** 자동 접근 및 표지·소개 저장/재게시 허용 범위, 다양한 출판사·분야의 새 ISBN 표본에서 3축·소개·표지 확보율, 전자책·세트·판본 오매칭, HTTP 200 빈 응답·차단·재시도 중단, ISBN 매핑, 과거 API 저장본과의 필드 비교. 두께의 공급처 간 수치 차이는 수용한 결정이며 동일값 확보를 재차 요구하지 않는다. 이번 4권으로 전체 성공률이나 안전한 호출량을 산정하지 않는다.
5. 기존 R2 우선 업로드·자사 URL만 DB 저장·원본 보관·동일 표지색 알고리즘·단일 트랜잭션은 유지한다. 대체 공급처의 판매지수를 알라딘 `salesPoint`와 섞거나 누락값을 0으로 만들지 않는다.

### 종료 공지

- **공식 페이지에서 확인:** [고객센터 FAQ](https://www.aladin.co.kr/cs_center/wcs_faq_list.aspx?UpperId=74)의 공지 목록에 `알라딘 OpenAPI 서비스 종료 안내(26.10.30)`가 있고, [기존 종료 공지](https://blog.aladin.co.kr/cscenter/17483675)를 가리킵니다.
- **이번 조사에서 미확인:** 공지 본문은 웹 도구에서 HTTP 403으로 읽지 못했습니다. 기존 [마이그레이션 계획서](book-data-migration-plan.md#알라딘-종료-일정-확정)에 기록된 상세 종료 범위·키 발급 종료일을 이번에 본문으로 재확인하지는 못했습니다. API 실제 응답이나 CDN의 지속 보장과는 별개입니다.

### 이용약관과 저장·재사용

- **직접 HTTP 확인:** 사이트 하단 이용약관 링크인 [알라딘 이용약관](https://www.aladin.co.kr/account/waccount_provision.aspx?pType=1)을 11/1에 직접 읽었습니다. 시행일·최종변경일 표기는 모두 **2026-09-15**입니다. 웹 검색 도구가 먼저 반환한 2026-02-02 캐시본은 최신판 판단 근거에서 제외했습니다.
- **제21조:** 사이트 정보의 사전 승낙 없는 영리 목적 복제·송신·배포와 제3자 이용을 제한합니다. **제19조:** 과도한 반복·연속 대량 열람·다운로드 등의 이용 패턴을 부정이용으로 분류하고 이용량 관련 운영 기준을 둘 수 있다고 명시합니다. 표지 파일과 소개글을 북적 R2·DB에 계속 저장해 서비스하는 사용권이 공개 열람만으로 주어진다고 판단할 근거는 없습니다. 적용 여부·권리 범위는 기술적 수집 가능성과 구분해 확인해야 합니다. ([공식 약관](https://www.aladin.co.kr/account/waccount_provision.aspx?pType=1))
- **참고용 기존 API 조건:** [OpenAPI 이용약관](https://blog.aladin.co.kr/openapi/13851154)의 공식 검색 색인에는 허용 범위를 벗어난 복제·저장(캐시 포함)·가공·배포 제한 및 결과 데이터 권리의 귀속이 나타납니다. 이 페이지 본문도 이번에 403으로 열리지 않았으며, API 조건을 웹 수집 허가로 해석해서는 안 됩니다.
- **직접 HTTP 확인:** [robots.txt](https://www.aladin.co.kr/robots.txt)는 웹 도구에서는 열리지 않았지만, 부모 조사에서 11/1 직접 내려받은 원문(`/tmp/bookjeok-aladin-robots.txt`)을 확인했습니다. 파일 표기 갱신일은 2026-10-13입니다. 일반 수집기에게 적용되는 `User-agent: *`의 규칙은 `Disallow: /`입니다. 일부 검색·사용자 요청 봇에는 별도 허용과 3초 또는 5초 지연이 있으나, 그 그룹에서도 검색·API·TTB 등의 경로는 제외됩니다. 따라서 **북적 전용 일반 크롤러가 허용됐다고 볼 수 없습니다.** 허용 봇 이름을 사칭하는 설계는 하지 않습니다. robots 허용 여부와 콘텐츠 저장·재게시 권리는 서로 다른 확인 항목입니다.
