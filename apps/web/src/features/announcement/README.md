# Frontend Feature: Announcement (새 기능 소개)

새 기능을 서비스 접속 시 한 번, 넘겨 보는 모달로 소개합니다. 서버·DB 없이 프론트에서만 동작합니다.

## 폴더 구조

```
announcement/
├── constants/announcements.ts        # 공지 목록(id·기간), 고르기, 띄울 경로
├── stores/use-announcement-store.ts  # 본 공지 id (localStorage, 기기에만)
├── types.ts                          # AnnouncementProps (소개 모달이 받는 open·onOpenChange)
├── components/
│   ├── announcement-host/            # 언제 띄울지 판단. DefaultLayout에 붙어 있음
│   ├── feature-carousel/             # 넘겨 보기 모달 (스와이프·화살표 키·점)
│   └── reading-tower-intro/          # 책탑 소개 4장 (+ stories)
└── __tests__/
```

## 동작

- **기간**: 공지마다 `from`~`until`(KST)이 있습니다. 기간이 지나면 새로 온 사용자에게 "새 기능"으로 띄우지 않습니다. 책탑은 2026-09-26~10-25(30일)입니다.
- **한 번만**: 닫으면(✕·바깥 클릭·Esc·마지막 버튼) 본 것으로 기록합니다. 기기에만 두므로 다른 기기에서는 한 번 더 뜰 수 있습니다.
- **어디서**: 비로그인은 홈(`/`)에서만 띄웁니다. 검색으로 책 상세에 처음 들어온 사람의 첫 화면을 가리지 않기 위해서입니다. 로그인했으면 기본 레이아웃을 쓰는 어느 페이지에서든 띄웁니다. 남의 공개 책탑(`/users/*`)과 로그인·가입 화면에서는 띄우지 않습니다.
- **언제**: 페이지가 뜨고 1.5초 뒤에 엽니다. 그때 다른 모달이 열려 있으면 이번에는 건너뛰고(본 것으로 치지 않음) 다음 이동 때 다시 봅니다.
- **알림으로 보내지 않는 이유**: 알림은 나에게 일어난 일(댓글·거래·채팅)을 알리는 곳이라 공지를 섞으면 신뢰가 떨어지고, 모든 사용자에게 알림 행을 만들려면 서버 작업과 수동 DDL이 필요합니다. 알림 목록 한 줄로는 애니메이션도 보여 줄 수 없습니다.

## 책탑 소개

실제 무대(`TowerStage`)를 그대로 씁니다. 슬라이드가 보일 때만 마운트되므로 들어올 때마다 책이 다시 떨어집니다.

1. 책이 한 권씩 떨어지는 책탑. 로그인했고 올해 기록이 있으면 내 책탑("벌써 94.9cm 쌓였어요"), 아니면 예시 46권(`reading-log/.../lib/sample-books`)
2. 내 캐릭터와 나란히 (말풍선·남은 높이)
3. 작가 비교. 카프카부터 2.6초마다 바뀌고, 이름을 누르면 그 작가에서 멈춥니다
4. 「읽었어요」 알림 모형. 마지막 버튼은 로그인이면 「내 책탑 보러 가기」, 비로그인이면 「가입하고 책탑 쌓기」(로그인 화면으로, 돌아올 곳을 책탑으로 저장)

## 새 공지 추가

세 곳만 건드리면 됩니다. 모달·기간·한 번만 띄우기·경로 판단은 그대로 씁니다.

1. `constants/announcements.ts`의 `ANNOUNCEMENTS`에 `{ id, from, until }` 추가
2. `components/<기능>-intro/`에 소개 컴포넌트 작성. `AnnouncementProps`(open·onOpenChange)를 받아 `FeatureCarousel`에 슬라이드 배열(그림·제목·본문)과 마지막 버튼을 넘깁니다. 문구는 `announcement.<id>` 아래에 둡니다
3. `announcement-host`의 `INTROS`에 id와 컴포넌트를 `dynamic`으로 등록. 빠뜨리면 타입 검사에서 걸립니다

기간이 겹치는 공지가 여럿이면 한 번에 하나만, 목록 순서대로 접속할 때마다 차례로 뜹니다.
