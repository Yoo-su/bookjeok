# Frontend Feature: Cat Cameo (가끔 나타나는 검정고양이)

독서 키재기 맨 위 책에 앉은 검정고양이가 특정 기능과 상관없이 북적 어디서든 가끔 나타납니다. 화면 틀(상단바, 화면 아래 모서리)을 넘나드는 것이 요점입니다. 서버·DB 없이 프론트에서만 동작합니다.

## 폴더 구조

```
cat-cameo/
├── constants.ts                      # 장면 목록, 빈도 규칙(CAMEO_RULES), 조용히 할 경로
├── lib/
│   ├── schedule.ts                   # 나올지·어느 장면인지 고르기(순수 함수) (+ test)
│   ├── draw.ts                       # 걷는 옆모습·빼꼼 정면 그림 (+ test)
│   └── free-gap.ts                   # 상단바에서 멈춰 설 빈 틈 고르기 (+ test)
├── stores/use-cat-cameo-store.ts     # 오늘 나온 횟수·마지막 장면 (localStorage)
└── components/
    ├── host/cat-cameo-host/          # 언제 띄울지 판단. [locale]/layout에 붙어 있음
    └── scenes/
        ├── header-walk/              # 상단바 알약 안을 걸어 지나감(스프라이트 정의는 walk.json·walk-sprite.ts)
        ├── bottom-peek/              # 화면 아래 모서리에서 빼꼼
        └── cat-cameo.stories.tsx     # 장면 반복 재생·정지 자세
```

## 장면

- **상단바 산책(walk)**: 상단바 알약(`[data-site-header] > div`) 안쪽 바닥을 옆모습으로 걸어 지나갑니다. 알약 둥근 끝에서 나타나 반대쪽 끝으로 사라집니다. 로고·메뉴·버튼이 없는 빈 틈에서 옆모습 그대로 멈춰 서서, 천천히 한 번(고양이의 "편하다"는 인사)·짧게 한 번 눈을 깜빡인 뒤 다시 걷습니다. 눈꺼풀은 털색 타원이 위에서 내려와 덮는 방식이고 눈 자리는 `walk.json`의 `restEye`입니다. 걸을 때는 8프레임 스프라이트(9번째 칸은 정지 자세)를 쓰고, 이동 속도를 보폭에 맞춰 디딘 발이 미끄러지지 않습니다. 알약 폭이 260px보다 좁으면 나오지 않습니다.
- **아래에서 빼꼼(peek)**: 화면 아래 왼쪽이나 오른쪽 모서리에서 귀 끝부터 올라와 갸웃하고, 눈까지 올라와 앞발로 모서리를 붙잡고, 왼쪽·오른쪽을 보고 깜빡인 뒤 쏙 내려갑니다(약 5초). 가운데의 빠른 메뉴(BottomDock)와 겹치지 않게 모서리 쪽에만 나옵니다.
- **누르면**: 산책 중이면 들킨 듯 움찔(발밑 기준으로 납작했다 부르르)한 뒤, 돌아서 점점 빨라지며 하던 방향으로 내달리고(뛰어오르지 않음), 빼꼼이면 쏙 숨습니다. 안내 문구·만난 횟수·축하 효과는 두지 않습니다. 설명하지 않고 고양이만 둡니다(2026-11-05 결정).

스프라이트는 `apps/web/public/cat-cameo/`에 있으며 각 장면을 띄울 때 불러옵니다. 캐시된 그림은 SVG `<image>`가 화면에 붙기 전에 load가 끝나 onLoad를 놓치고, 그러면 고양이가 숨은 채 멈춰 그 페이지에서 다시 나오지 않았습니다. 그래서 `scenes/use-sprite-ready.ts`가 그림을 따로 불러온 뒤 장면을 시작합니다(2026-11-07). 빼꼼은 다섯 표정을 쓰고, 화면 가장자리 위아래로 움직이는 효과는 별도로 적용합니다. 상단바에서 멈출 때는 걷기 스프라이트의 정지 프레임(9번째 칸)을 씁니다.

## 언제 나오나

`CAMEO_RULES`에서만 고칩니다.

- 페이지에 들어와 4~10초 머문 뒤 45% 확률로 주사위를 굴립니다. 빗나가도 같은 페이지에 머무는 동안 35~60초마다 30% 확률로 다시 굴립니다.
- 세션(탭)당 3번, 다음 등장까지 90초, 하루 8번까지입니다. 바로 전과 다른 장면을 고릅니다.
- 2026-11-07에 빈도를 올렸습니다. 이전 규칙(6~20초 뒤 30% 한 번, 세션 2번·간격 3분·하루 4번)은 페이지를 빨리 넘기거나 한 페이지에 오래 머무는 사용자가 거의 만나지 못했습니다.
- 쓰거나 결제하는 화면(로그인·가입·리뷰 쓰기·판매 등록·`/edit`·주문·관리자)에서는 나오지 않습니다.
- 그 순간 다른 창(`role="dialog"`)이 떠 있거나, 입력칸에 커서가 있거나, 탭이 가려져 있으면 건너뜁니다.
- 기기 설정이 "동작 줄이기"면 나오지 않습니다.

## 확인하기

- 스토리북 `Features/CatCameo/Scenes`: 장면을 반복 재생합니다. 고양이를 눌러 반응을 봅니다. `StillPoses`는 걸음 자세를 크게 멈춰 보고, `ActualSize`는 실제 헤더에 등장하는 크기로 봅니다.
- `Features/CatCameo/Scenes/OnRealHeaderAndFooter`에서 실제 헤더와 푸터를 띄우고, 버튼으로 두 장면을 바로 재생합니다. 빼꼼은 푸터의 위치와 관계없이 화면 아래 모서리에 나옵니다.
- 실제 화면에서는 주소에 `?cat=walk` 또는 `?cat=peek`를 붙이면 한도·확률 없이 0.9초 뒤에 나옵니다(기록하지 않음).

### 아기고양이 디자인 적용 (2026-11-05)

- 옆모습의 주둥이는 짧게, 볼은 둥글게 그렸습니다. 걷기와 빼꼼의 모든 프레임, 멈춰서 보는 정면에 둥근 꿀색 눈과 작은 코를 적용했습니다.
- 뒷다리 폭만 줄였던 시안은 폐기했습니다. 네 다리를 허벅지부터 둥근 발끝까지 이어진 곡선으로 다시 그렸습니다. 꼬리도 짧고 가늘게 맞췄습니다.
- 헤더 산책·정면·빼꼼과 모든 스토리에 적용했습니다. 독서 키재기의 책 위 고양이도 같은 아기고양이 얼굴로 통일했으며 공유 이미지에도 반영됩니다.
- 등장 빈도·애니메이션 시간·클릭 반응은 유지합니다.

### 걷기 원화 교체 (2026-11-07)

- 예전 걷기 그림은 디딘 발이 프레임마다 앞뒤로 미끄러지고, 가까운 다리와 먼 다리가 같은 검정이라 좌우가 번갈아 나가는 게 보이지 않았습니다. 이동(초당 70~140px)도 이 크기 고양이가 발을 붙이고 걷는 속도(초당 40px 안팎)보다 최대 네 배 빨랐습니다.
- 새 그림은 예전 1번 프레임의 머리·몸통·꼬리 픽셀을 그대로 두고, 다리만 고양이 걸음 순서(같은 쪽 뒷발 → 앞발, 디딘 발은 프레임마다 8px씩 뒤로)에 맞춰 로컬 이미지 생성 모델로 다시 칠했습니다. 걸음에 맞춰 엉덩이가 오르내리고 머리가 살짝 끄덕이며 꼬리가 흔들립니다.
- `walk.json`의 `walkFrames`(걸음 프레임 수)·`restFrame`(정지 자세 프레임)·`stride`(한 바퀴에 나아가는 칸 px)로 동작을 정합니다. `stride`가 있으면 산책 속도를 보폭에 맞추고 다리 프레임도 이동과 같은 easing으로 돌립니다. 그래서 데스크톱 상단바를 건너는 데 약 27초(예전 약 7초), 휴대폰은 약 9초가 걸립니다.
- 누르면 깜짝 뛰던 동작은 로봇 같아 뺐습니다. 0.4초 동안 움찔하고, 걷던 속도에서 끝 속도(초당 약 500px)까지 빨라지며 내달립니다. 거리에 따라 2초 안팎 걸립니다.
- 멈춰 고개를 돌려 이쪽을 보던 동작은 뺐습니다. 코드로 그린 정면 얼굴, 빼꼼 얼굴을 얹은 것, 생성 모델로 다시 칠한 것 모두 옆모습과 이어지지 않아(얼굴·목이 따로 놀거나 볼이 찌그러짐) 기각됐습니다. 다시 넣으려면 옆모습과 같은 그림체의 정면 원화(머리·목이 이어진)가 필요합니다.
