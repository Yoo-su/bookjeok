## 2. 두 개의 축

이 기능은 성격이 다른 두 화면을 함께 담고 있습니다.

|        | 개인 독서 기록                         | 독서 라운지              |
| ------ | -------------------------------------- | ------------------------ |
| 라우트 | `/my-page/reading-log`                 | `/lounge`                |
| 접근   | 본인만                                 | 공개                     |
| 구성   | calendar-view · list-view · stats-view | lounge-feed/\*           |
| 데이터 | `/reading-logs?year=`                  | `/reading-logs/lounge/*` |

라운지 공개 여부는 `/reading-logs/settings`로 사용자가 직접 제어합니다.

## 3. 핵심 로직

### 캘린더

`reading-log-calendar`가 그해 기록을 한 번에 받아(`useReadingLogsQuery({ year })`) 그리는 달 것만 `reading-log-day-cell`에 배치하고, 셀을 클릭하면 `day-details-dialog`가 그날의 완독 도서와 한 줄 메모를 보여줍니다. 작성·수정은 `reading-log-form-dialog`에서 처리합니다. `use-seasonal-theme`은 월에 따라 계절을 고르지만, 실제로 바뀌는 것은 히어로의 계절 그림·필터·라벨뿐입니다(배색 값은 네 계절이 모두 같은 stone 계열).

**연 단위 조회** (2026-10-06): 예전엔 달마다 그 달 목록·통계를 받고 앞뒤 달을 미리 받아 달을 넘길 때마다 요청이 최대 6개 나갔고, 표지도 그 달이 도착한 뒤에야 받았습니다. 지금은 한 해 목록 하나(`readingLogKeys.list({ year })`, `readingLogsYearQueryOptions`, staleTime 5분)를 달력·통계·날짜 상세·dock 달력 패널·미리 받기가 함께 씁니다.

- 같은 해 안에서 달을 넘기면 요청이 없습니다. 1·2월이면 지난해, 11·12월이면 다음 해를 미리 받고(미래는 빼고, 경계 한 달 앞에서 받아 하나씩 넘길 때 경계에서 기다리지 않음), 앞뒤 달 칸의 맨 앞 표지를 `new Image()`로 미리 받습니다(`use-reading-log-prefetch`).
- 통계(이달·올해 권수)는 같은 목록에서 셉니다. 서버 `getStats`도 기간 안의 기록 수를 세는 것이라 기준이 같습니다. `/reading-logs/stats` 엔드포인트는 서버에 남아 있지만 웹은 쓰지 않습니다.
- 달 넘김 슬라이드의 대기(`keepPrevious`·흐려짐·`aria-busy`)는 미리 받지 않은 해로 건너뛸 때만 남습니다. 그리는 달(`shownMonth`)과 통계 제목은 그해 기록이 있어야 넘어갑니다.
- 칸에는 그리는 달 기록만 둡니다. 첫·끝 줄의 이웃 달 칸은 그해 기록이 있어도 비워 둡니다(월 단위 조회 때와 같음). 예시 달력(`readOnly`)은 전처럼 넘겨받은 예시를 그대로 씁니다.
- 목록 응답의 책은 `ReadingLogBook`(isbn·제목·저자·출판사·표지)만 담습니다. 소개(`description`)가 응답 대부분이라 서버 `findAll`에서 뺐습니다(2026-10-06 실측, gzip: 84권 85KB → 10KB, 17~18권 15~19KB → 3~4KB).
- 받는 동안 남아 있는 이전 달은 `inert`라 마우스·Tab·Enter 모두 지난 기록을 열지 않습니다.
- 상단 연·월 숫자(`TurningNumber`)와 달 그리드는 같은 박자(`MONTH_TURN`, 0.26초)·같은 방향으로 넘어갑니다. 둘 다 `transform` 문자열로 움직여 합성 스레드에서 돌고, 새 달 칸을 그리느라 메인 스레드가 바빠도 끊기지 않습니다. 이 방식은 `MotionConfig`의 동작 줄이기가 적용되지 않아 `useReducedMotionConfig`로 직접 밀지 않게 합니다. 숫자는 나가는 것과 들어오는 것 둘만 그려 연타해도 쌓이지 않습니다.

모바일(sm 미만)은 칸이 약 45px로 좁아 날짜 줄·제목을 두면 표지가 작아지므로, dock 달력 패널과 같은 `cover-day-cell`(표지가 칸을 꽉 채우고 날짜는 표지 위 칩)로 그리고 칸 사이를 띄웁니다. sm 이상은 선으로 나눈 표(줄 160px, 표지+제목) 그대로입니다. 두 칸을 모두 그리고 CSS로 하나만 보여 화면 폭 판정 없이 서버 렌더와 맞습니다(`display:none`은 그리드 칸을 차지하지 않음).

### 공개 소개 페이지 `/reading-log`

독서 기록은 로그인 뒤(`/my-page/reading-log`, noindex)에 있어 검색엔진이 볼 수 있는 페이지가 없었습니다(2026-09-28 추가). 구성은 `/reading-height`와 같습니다. 소개 글·이용 방법·FAQ는 서버에서 렌더링하고(FAQPage·BreadcrumbList JSON-LD), 예시 달력(`reading-log-demo`)만 브라우저에서 움직입니다.

- 예시 달력은 `ReadingLogCalendar`의 `readOnly`에 예시 46권(`sample-books`)을 기록으로 바꿔 넘깁니다. 조회·통계·보기 전환이 없고, 날짜를 누르면 읽기 전용 상세가 열립니다. 예시가 있는 2026년 1~9월 밖으로는 넘어가지 않습니다.
- 시작 버튼(`reading-log-start-link`)은 보기를 달력으로 바꿔 독서 기록으로 보내고, 비로그인이면 마이페이지 가드가 로그인 뒤 돌려보냅니다. 독서 키재기 소개의 시작 버튼도 같은 컴포넌트에 `view="stack"`을 넘깁니다.
- 기능 목록의 「독서 키재기」 칸이 `/reading-height`로 잇습니다. 독서 기록이 상위, 독서 키재기는 그 안의 한 보기입니다.
- 헤더·모바일 메뉴의 「독서 기록」은 비로그인이면 이 소개로, 로그인했으면 내 독서 기록으로 갑니다. 마이페이지 가드는 그대로 로그인으로 보냅니다. 북마크나 만료된 로그인으로 들어온 기존 사용자에게 소개를 끼우지 않고, 소개의 시작 버튼이 가드와 소개 사이를 돌지 않게 하려는 것입니다.
- 사이트맵·푸터·사이트 내비게이션 JSON-LD에 넣었습니다. 링크 미리보기는 전용 카드가 없어 기본 로고 카드입니다.
- 메모 글자 수는 문구에 박지 않고 `MAX_MEMO_LENGTH`(core)를 `{max}`로 넣습니다.

### 하단 dock 패널 (보기 전용)

로그인하면 하단 dock에 기록 달력과 독서 키재기가 생기고, 어느 페이지에서든 패널로 엽니다(데스크톱 카드·모바일 시트, `shared/components/ui/dock-panel.tsx`). 패널은 **보기 전용**입니다. 페이지 → 패널 → 모달로 층이 쌓이면 닫기·Esc가 무엇을 닫는지 흐려지므로, 기록을 남기는 일은 페이지로 넘깁니다.

- **기록 달력**: 칸 전체를 표지로 쓰고 날짜는 표지 위에 얹습니다. 날짜 줄을 따로 두지 않아 좁은 화면에서도 표지가 큽니다(375px 폰 기준 약 47×62px, 페이지 모바일 달력보다 큼). 표지는 `unoptimized`로 페이지 달력과 같은 주소를 써 브라우저 캐시를 공유합니다. 날짜를 누르면 `?date=`로 독서기록 페이지의 그날 상세가 열리고, 「독서기록에서 크게 보기」는 `?view=calendar&month=`로 같은 달을 엽니다. 달을 넘겨도 패널 높이가 출렁이지 않게 늘 6주를 그리고, 기록 없는 달 안내는 날짜 칸 위에 겹쳐 띄웁니다(아래 줄에 끼우면 기록을 받은 뒤 높이가 바뀜). 페이지 달력과 같은 그해 캐시를 써서 같은 해 안에서는 요청 없이 넘기고, 이웃 해와 앞뒤 달 표지는 `useReadingLogPrefetch`로 미리 받습니다.
- **독서 키재기**: 페이지와 같은 기준(무릎 아래면 사물 비교)으로 높이·문장·진행률 카드(`StackProgress`·`StackObjectProgress`)를 보여 주고, 페이지·공개 프로필과 같은 연필 무대(`StackStage`, 사람·사물 없이 쌓은 책만)와 최근 표지 6권(한 줄)을 곁들입니다. 무대가 240px로 작아 다독이면 축척을 따라 책 폭까지 줄어 바늘처럼 가늘어지므로 `minStackWidthPx={30}`으로 **폭만** 하한을 둡니다(높이·눈금은 그대로, 비교 대상이 없을 때만 적용). 46권은 거의 그대로, 322권(6.6m)은 4px 바늘 대신 30px 기둥이 됩니다. 패널이 **다 열린 뒤**(`useDockPanelSettled`) 무대를 붙이고 책을 떨어뜨리며, 무대를 누르면 페이지의 키재기로 갑니다. 진행률은 패널 안에서 테두리 없이(`plain`) 무대 옆에 두고, 권수·쪽수·무게 합계는 그 칸이 좁아 넘치므로 무대 아래 전체 폭으로 뺍니다(`hideStats`). 무대 칸은 모바일 7.5rem, 데스크톱 카드 8.5rem(패널 28rem)이고, 360px 미만에서는 무대를 위로 올립니다. 공유와 키 입력은 페이지에서 합니다.
- **첫 열림이 끊기지 않게** (2026-10-04): 패널이 열리는 0.38초에 무대 그리기·책 위치 재기·데이터 응답이 몰려 첫 열림이 삐걱거렸습니다(CPU 4배 감속 측정에서 모바일 열림 중 프레임 2~12개, 최장 0.4초 멈춤). 세 가지로 나눴습니다. ① 무대는 열림이 끝난 뒤 붙임(위 `useDockPanelSettled`). ② 달력·키재기 아이콘에 손이 닿으면(마우스 올림·터치 시작·포커스, `onIntent`) 데이터와 최근 표지를 미리 받음(`use-dock-peek-prefetch`). ③ 같은 순간 패널을 닫힌 채 미리 그려 둠(`DockPanel warm`). 같은 측정에서 열림 0.4초 동안 프레임 23~24개, 최장 약 40ms가 됐습니다.
- **독서기록 페이지에서는** 두 아이콘이 패널을 열지 않고 페이지 보기를 바꾼 뒤 맨 위로 올립니다(탭바 재탭과 같음). 지금 보기에는 아이콘 아래 점과 `aria-current`가 붙습니다.
- **딥링크**: `views/reading-log-view/reading-log-deep-link.tsx`가 주소를 한 번 읽어 적용하고 지웁니다. 새로고침·뒤로가기로 상세가 다시 뜨지 않습니다. 날짜는 로컬 자정으로 읽고(UTC로 읽으면 하루 밀림), 미래 날짜는 달만 열고 상세는 띄우지 않습니다. 상세는 그해 기록을 받고 그 달로 넘어간 뒤 한 번만 띄웁니다(부모가 날짜를 비우기 전에 다시 그려져도 ref로 막음).

### 기록 진입 경로

- 캘린더 날짜 칸 → `day-details-dialog` → 도서 검색 → 폼. 지난 날짜를 채울 때 씁니다. dock의 기록 달력에서 날짜를 눌러도 이 경로로 들어옵니다.
- 도서 상세의 `mark-as-read-button` → 폼. 날짜 기본값은 오늘입니다. 비로그인이면 복귀 경로를 저장하고 로그인으로 보냅니다.
  - 폼을 열 때만 내 기록 이력(`useReadingLogBookStatusQuery`)을 조회합니다. 페이지만 보고 나가는 방문에는 요청이 늘지 않습니다. 이미 기록한 책이면 날짜 아래에 안내합니다. 고른 날짜가 마지막 기록일과 같으면 「이날 이미 기록」(저장하면 409), 다르면 「N번 기록한 책, 다시 읽었다면 그대로 기록」입니다. 생성 폼에서만 띄웁니다.
  - 저장하는 동안에는 조회를 멈춥니다(`enabled: open && !isPending`). 생성 뮤테이션이 `readingLogKeys._def`를 무효화할 때 닫히는 폼에서 다시 조회하지 않게 하려는 것이고, 무효화된 이력은 다음에 열 때 새로 받습니다.

폼은 두 경로 모두 날짜를 바꿀 수 있고 미래 날짜는 막습니다. 같은 책·같은 날 중복은 서버가 409(`READING_LOG_002`)로 거절하고, 뮤테이션이 「그날 이미 기록한 책」 안내를 띄운 뒤 폼을 열어 둡니다. 뮤테이션은 성공 응답으로 그해 목록 캐시를 바로 고친 뒤 `readingLogKeys._def` 전체를 무효화합니다(`@bookjeok/react-query`의 `reading-log/cache.ts`). 실패하면 캐시를 건드리지 않으므로 되돌릴 것이 없습니다. 수정에서 날짜를 바꾸면 다른 해로 옮겨 갈 수 있어 모든 연 목록에서 빼고 새 해에만 날짜순으로 넣습니다. 날짜가 그대로면 제자리에서 바꿔, 같은 날 여러 권 중 맨 앞 기록의 메모만 고쳐도 그날 표지가 바뀌지 않습니다. 새 기록은 같은 날 기존 기록 뒤에 붙습니다. 생성·수정 모두 **캐시가 없는 해에는 심지 않습니다.** `[data]`를 심으면 그해가 한 권짜리로 먼저 그려집니다.

### 독서 키재기 (`stack-view`)

한 해에 읽은 책을 **실제 두께로** 눕혀 쌓고, 옆에 **사물** 또는 **사람**(입력한 키만 한 손그림 캐릭터·작가)을 세웁니다. 보기 전환의 「독서 키재기」 탭으로 들어오고, **마지막으로 본 보기를 기억**해 다음 방문 때 그대로 엽니다(`use-reading-log-view-store`). 데이터는 `GET /reading-logs/stack?year=`이고, 책 크기는 `book_dimensions`(알라딘 실측 수확본)에서, 없으면 서버가 추정합니다(`sizeSource`).

- **사물 사다리** (2026-09-27): 사람 옆에서는 한 해 20권(약 30cm)도 발목 근처라 티가 나지 않아 넣었습니다. 각설탕(1.6cm)·지우개·달걀·햄스터·연필 한 자루·소주병·닥스훈트·볼링핀·소화기·아델리펭귄·황제펭귄·농구 골대(림 3.05m)·기린(5m) 13개가 `lib/objects.ts`에 낮은 순으로 있고, **고르는 메뉴 없이** 쌓은 높이 바로 위의 사물이 다음 목표로 섭니다(다 넘으면 가장 큰 기린과 비교). 높이는 자주 소개되는 대략값이라 화면은 「약」을 붙입니다.
  - **사물/사람 탭**: 무대 위 두 칸 탭으로 바꿉니다. 사람 탭에서만 「내 키」 팝오버(나·작가)가 보입니다. 고르기 전에는 쌓은 책이 무릎(키의 28%) 아래면 사물, 위면 사람으로 열고, 한 번 고르면 기기에 기억합니다(`compareMode`).
  - **확대와 무대 높이**: 사물 무대는 사람 무대와 축척이 다릅니다. 눕힌 책의 가로(약 21cm)가 폭을 차지해 좁은 화면에서는 폭이 축척을 정하므로, 무대 높이를 내용만큼 줄입니다(`objectSceneHeight`, 200~600px). 가로 배치는 사람 무대처럼 눈금자 · 쌓은 높이 이름표 자리 · 쌓은 책 · 사물 · 오른쪽 여백 순이고, 넓은 화면은 폭의 84%만 채워 좌우를 비웁니다(좁은 화면은 여백을 줄여 96%). 작은 사물이라 사람 무대보다는 조금 더 확대돼 보입니다. 쌓은 높이 이름표는 눈금자에 걸치지 않고, 목표 이름표와 겹치면 아래로 비키거나(자리가 없으면) 적지 않습니다.
    - 한때 작은 사물을 키우려고 쌓은 책 왼쪽을 무대 밖으로 밀어 가까이 찍었다가 되돌렸습니다(2026-09-27). 무대가 꽉 차 갑갑하고 이름표가 눈금자에 얹혔습니다. 그래서 모바일의 첫 사물(각설탕·지우개)은 작게 보입니다.
    - 한 권이 1px보다 얇아지는 다독(300권 등)은 1px로 올리지 않고 실제 두께로 그립니다. 올리면 쌓은 높이가 눈금보다 커집니다(사람 무대도 같음). 사물↔사람을 바꿀 때만 높이를 트윈하고 처음 띄울 때는 트윈하지 않습니다(줄어드는 모습이 보이지 않게 그리기 전에 잰다).
  - **문구**: 말풍선은 남은 높이와 지금 목표를 넘자는 말입니다("2.3cm만 더!", "햄스터를 넘어 보자!"). 첫 문장·공유 부제도 다음 목표만 말하고(첫 문장은 "올해 넘은 사물은 3개예요"처럼 개수만), **지난 사물 이름은 말하지 않습니다.** 여러 권을 한꺼번에 기록하면 넘는 모습을 못 본 사물이 생겨 "닥스훈트는 넘었다!"가 뜬금없기 때문입니다(2026-09-28). 넘는 순간은 기록 직후 장면이 알립니다. 지난 연도 요약만 가장 높이 넘은 사물을 적습니다. 남은 높이는 사물 쪽 문구 모두 소수 한 자리입니다. 좁은 화면에서 "햄스터 약 11cm" 이름표가 말풍선과 부딪히면 "약 11cm"로 줄입니다(`myHeightShort`). 1m 이상은 m로 적습니다. 진행률 카드는 넘은 사물부터 다음 사물까지를 한 칸으로 보고, 13개를 점 사다리로 보여 줍니다(누르면 사물 도감).
  - **그림**: 캐릭터와 같은 연필로 그리고 유채색은 최근 읽은 책 색 한 곳뿐입니다(지우개 슬리브, 연필 몸통, 닥스훈트가 문 책 등). 그리는 법은 [캐릭터 그리기 가이드](components/stack-view/CHARACTERS.md)의 「사물」 절.
- **같은 축척**: 무대의 쌓은 책과 캐릭터는 같은 px/mm로 그립니다. 캐릭터는 인체 비율(무릎 28%·허리 60%·어깨 82%)이라 말풍선의 "허리까지 9cm"가 그림과 맞습니다. 작가 말풍선과 진행 눈금은 키 대비 퍼센트를 표시합니다.
- **장면 하나, 렌더러 둘**: `lib/scene.ts`가 도형 목록을 만들고, 화면은 SVG(`scene-svg.tsx`), 공유 이미지는 Canvas(`draw-canvas.ts`)로 같은 목록을 그립니다. 좌표를 px로 굳혀 두 결과가 같습니다.
- **공유**: 화면의 장면을 1080px 이미지(스토리 9:16·피드 4:5)로 그려, 모바일은 공유 시트, 데스크톱은 파일로 내보냅니다. 다이얼로그도 사물/사람 탭이 있고 화면에서 보던 탭으로 엽니다. 사람일 때만 「내 키」 버튼이 있어 키를 바꾸면 이미지를 다시 그립니다(150ms 모아서). 사물 장면은 폭이 축척을 정하므로 내용만큼만 그려 제목과 「쌓은 책」 목록 사이 가운데에 둡니다.
- **공유 → 프로필 링크** (2026-10-02): 이미지를 본 사람이 공개 프로필로 들어올 길입니다. 이미지 바닥글 주소가 `bookjeok.com/users/{handle}`이고, 다이얼로그에 프로필 링크 줄(「링크 복사」)이 있습니다. 링크는 `/{locale}/users/{handle}?year={연도}&ref=share`로 이미지와 같은 해를 엽니다. 「공유하기」는 링크를 클립보드에 함께 넣되 **공유 데이터에는 파일만** 담습니다. 링크를 섞으면 인스타 스토리처럼 이미지만 받는 앱이 공유 시트에서 빠질 수 있고, 스토리는 사용자가 링크 스티커에 붙여 넣는 방식입니다. 사파리는 `await` 뒤의 `share()`를 사용자 동작 밖으로 보므로 복사를 기다리지 않습니다. 독서 기록이 비공개면 링크로 온 사람이 빈 프로필을 보므로 같은 줄에서 알리고 「공개로 바꾸기」를 둡니다.
- **공유 이미지의 책 제목**: 쌓은 책은 한 권이 10px 안팎이라 제목을 쓸 수 없습니다. 바닥선 아래에 「쌓은 책」 목록(`lib/legend.ts`)을 범례처럼 두고, 줄마다 쌓은 책과 같은 손그림 책을 표지색으로 붙여 쌓은 책과 잇습니다. 목록 높이만큼 장면을 줄입니다. 기본은 맨 위(최근) 5권이고 다이얼로그의 「제목 넣을 책」에서 최대 5권(`LEGEND_MAX`)까지 바꾸며, 나머지는 「외 N권」으로 적습니다. 모두 빼면 목록 없이 그립니다. 부제(`-`, `:` 뒤)와 끝 괄호는 떼고 적습니다.
  - 제목마다 화살표로 쌓은 책을 가리키는 방식은 시도했다가 버렸습니다. 맨 위 몇 권이 수십 px 안에 몰려 화살표가 한곳으로 모여 꼬입니다. 무대 안 빈 곳에 목록을 두는 것도 「남은 높이」 표시와 캐릭터 사이가 좁아(스토리는 더 좁음) 들어가지 않습니다.
- **키는 서버에 보내지 않습니다.** `use-stack-settings-store`(localStorage)에만 둡니다. 입력 전에는 평균 키(남 173·여 161cm), 캐릭터는 `users.gender`(`'M' | 'F'`)로 시작합니다. 키 입력은 화면에 늘 펼쳐 두지 않고, 무대 위 「내 키 입력 / 내 키 170cm」 버튼의 팝오버(`stack-height-chip`)에 둡니다.
- **작가와 비교**: 키 설정 팝오버에서 내 키 또는 카뮈(약 176cm)·사르트르(약 153cm)·쿤데라(약 185cm)·울프(약 170cm)·카프카(약 182cm)를 고릅니다. 흔히 소개되는 추정값이며 설정에 출처 링크를 제공합니다. 선택 작가는 기기에 저장하고 내 키·남녀 캐릭터는 별도로 보존합니다(`use-stack-comparison`). 무대·진행률·화면/공유 문구가 같은 비교 대상을 사용합니다.

### 콩 (`kong`, 2026-10-07)

공개 프로필 독서 키재기에서 남의 기록에 보내는 리액션입니다. 댓글처럼 직설적이지 않게, 「읽느라 수고했다」는 작고 까만 경의 한 알만 보냅니다. 규칙과 API는 서버 README 「콩」.

- **그림**: 키재기와 같은 연필(`stack-view/lib/pencil.ts`)로 그립니다(`kong/lib/kong-art.ts`). 몸은 순검정이 아닌 다크 그레이(`#3A3633`, 순검정이면 연필 윤곽이 묻힘), 크림색 점눈·작은 웃는 입·바깥 끝이 처진 팔자 눈썹. 눈썹은 40px 아래에서 빼고, 점눈은 작게 그려도 1px 아래로 줄지 않습니다. 표정은 `smile`(평소)·`squeeze`(눈 질끈, 바둥·비행)·`sleep`(받은 콩이 없을 때)·`joy`(^^ 눈, 콩 점프)·`shiver`(물결 입, 부르르). 팔다리는 바둥·걷기의 두 프레임(`flail0`·`flail1`), 점프 중 만세(`cheer`), 부르르 떨림 선(`brr`). 같은 그림은 `KongFigure`가 캐시해 다시 그리지 않습니다. 시안 단계에서 콩 배꼽(hilum)·감자형 몸·큰 흰자 눈은 기각했습니다.
- **보는 사람별 콩 줄**(`stack-book-dialog`의 `kong` prop): 공개 프로필에서 남의 기록이면 `KongVisitorRow`, 내 프로필·내 독서 키재기면 `KongOwnerRow`.
  - 비로그인: 콩이 바둥거리고 로그인 말풍선(로그인 뒤 돌아올 주소 저장). 바로 로그인 화면으로 넘기지 않습니다.
  - 안 보냄: 누르면 납작 → 「콩!」 → 포물선으로 빙글 날아 표지 오른쪽 위에 착지. 누르는 즉시 보낸 목록(`readingLogKeys.kongsSent(handle)`)에 넣고 실패하면 되돌립니다. 날아가는 콩은 다이얼로그가 transform 안이라 `document.body`로 포털하고, 앉는 콩은 표지 요소로 포털합니다. 탭을 옮겨 프레임이 멈추면 비행 시간 뒤 강제로 앉힙니다.
  - 이미 보냄: 표지 위 내 콩만. 누르면 바둥.
  - 내 기록: 받은 콩(5알까지 그림)·보낸 사람(셋 넘으면 「외 N명」). 없으면 자는 콩, 비공개면 「받을 수 없어요」.
- **받은 콩 모아 보기**: 독서기록 hero 우상단의 **종이 동그라미**(사진 위라 크림색 바탕·검은 테두리, 눈길을 끌지 않게 콩 한 알 크기, 스티커처럼 2° 기울임, 오른쪽 끝은 공개 스위치와 맞춤). 받은 수는 왼쪽 아래 배지(세 자리부터 99+). 누르면 **콩 종지**(30알까지 아래 줄부터 소복이, 시드 고정이라 자리가 같음). 종지를 누르면 차례로 튀어 오르고 한 알을 누르면 그 콩만 바둥. 아래 목록을 누르면 그날 상세로(`applyLink({ date })`). 받은 콩이 없으면 자는 콩이 「콩이란?」을 열고, 비공개이면서 받은 콩이 없으면 숨깁니다.
- **기록 곳곳의 표시**: 달력 칸(데스크톱은 날짜 줄 오른쪽 `KongBadge`, 모바일은 표지 오른쪽 위 흰 테두리 콩), 목록·하루 상세의 「콩 N · 보낸 사람」. 모두 `useReceivedKongMap`으로 같은 캐시(`kongsReceived`)를 봅니다. 공개 소개 페이지의 예시 달력(readOnly)에서는 받지 않습니다. 콩을 받은 기록을 지우면 확인 창에 「받은 콩 N알도 함께 사라져요」를 덧붙입니다.
- **갱신**: 기록 뮤테이션이 `readingLogKeys._def`를 무효화하므로 받은 콩도 다시 받습니다. 콩 알림이 실시간으로 오면 `kongsReceived`만 따로 무효화합니다(`notification` README).
- **콩이 많을 때·좁은 화면**: 서버는 기록마다 보낸 사람을 최근 10명(`KONG_SENDERS_PER_LOG`)까지만 주고 「외 N명」의 N은 `count`로 셉니다. 큰 수는 쉼표(번역은 `{count, number}`, 화면 숫자는 `toLocaleString`), 달력 칸은 세 자리부터 99+. 내 기록 줄의 콩은 좁은 화면에서 셋까지. 한 줄로 자르는 글자가 부모를 넓혀 가로 스크롤이 생긴 적이 있어(2026-10-07, 긴 책 제목이 콩 종지 시트를 570px로 넓힘) 다이얼로그는 `grid-cols-1`로 칸을 폭에 묶고, `ScrollArea`처럼 내용에 맞춰 늘어나는 부모 안의 콩 줄은 이름 칸을 `minmax(0, 1fr)` 그리드로 둡니다. Storybook `KongPill/Many`·`StackBookDialog/OwnerMany`와 달력 스토리(128알·긴 닉네임)로 320·375·768·1280px에서 넘침이 없는지 봅니다.
- **누를 때 반응**: 콩을 찔러 보는 곳(종지·내 기록 줄·표지 위 콩·「콩이란?」)은 `poke`로 바둥·부르르·콩 점프 중 하나를 고르고 같은 동작을 연달아 고르지 않습니다. 비로그인 보내기 버튼의 바둥은 로그인을 권하는 신호라 `flail`로 고정합니다.
- **프로필 메뉴**: 사용자 메뉴 「독서 기록」 옆에 받은 콩 수(`KongMenuCount`, 1알 이상일 때만). 헤더에 상시로 두는 안은 콩이 주객전도되고 대부분 0이라 기각했습니다(2026-10-07). 아바타에 손을 대는 순간 `receivedKongsQueryOptions`로 미리 받습니다.
- **동작 줄이기**: 날아가기·바둥(팔다리·흔들기)·튀어 오르기를 빼고 표정만 잠깐 바꿉니다. 선 떨림(`stack-boil`)과 자는 콩의 z도 멈춥니다.
- 확인: Storybook `Features/ReadingLog/Kong/*`, `Features/ReadingLog/Stack/StackBookDialog`(방문자·이미 보냄·비로그인·내 기록·없음·비공개), `Features/ReadingLog/ReadingLogCalendar`(7월에 받은 콩), `pnpm vitest run src/features/reading-log/__tests__/kong.test.tsx`.

### 북적 책동산 (2026-09-30)

독서 키재기가 한 사람의 한 해라면, 북적 책동산은 **공개 설정 사용자 전체의 기록을 한 산으로** 쌓은 것입니다. 교보·알라딘처럼 신간·베스트셀러를 계산할 수 없으니, 사용자가 쌓는 기록 자체를 「서비스가 살아 있다」는 신호로 쓰려는 것입니다. 「책탑」은 경쟁 서비스의 대표 기능 이름이라 쓰지 않습니다(위 「이름」 참고).

- **데이터**: `GET /reading-logs/lounge/mountain`. 높이(두께 합)·권수·독자 수·이번 주(7일) 증가분·지층 띠·막 올라온 책 8권·넘은 이정표. 순서는 독서 날짜가 아니라 **기록한 시각**입니다(지난 책을 몰아 기록하는 일이 많음). 비공개 사용자의 기록은 높이에도 넣지 않습니다.
- **산 모양**: 한 줄로 쌓으면 탑이 되므로 높이보다 넓은 산으로 그립니다. 윤곽은 어깨와 둘째 봉우리가 있는 손그림(`mountain-shape.ts`)이고, 띠는 이 윤곽으로 잘라 칠합니다(그리는 법은 캐릭터 가이드의 「책동산 하늘과 산」). **높이만 실제**이고 너비(넓은 화면 높이의 1.7배, 좁은 화면 1.35배)는 뜻이 없습니다. 몸통은 권마다 표지색 띠 하나이고, 240권을 넘으면 서버가 이웃한 책을 묶어 띠 수를 240개로 가둡니다.
- **이정표 사다리**: `MOUNTAIN_LANDMARKS`(core). 황제펭귄·농구 골대·기린(사물 사다리와 같은 그림) → 첨성대 → 석가탑 → 이순신 장군 동상 → 자유의 여신상 → 남산서울타워 → 63빌딩 → 롯데월드타워 → 한라산 → 백두산 → 에베레스트. 2026-09-30 기준 약 3.9m, 출시 주간 뒤로는 주 25cm 안팎이라 낮은 쪽을 촘촘히 뒀고, **그림은 첨성대까지만** 있습니다. 그림이 없는 이정표는 점선과 이름만 서므로 책동산이 가까워지면 그때 `figure-landmarks.ts`에 그립니다. 높이는 흔히 소개되는 대략값이라 화면은 「약」을 붙입니다.
- **넘은 이정표**: 서버가 누적 두께로 각 이정표를 처음 넘긴 기록을 찾아 돌려주고, 무대는 산비탈에 깃발로, 목록은 「9월 27일 · ○○님의 『책』으로 넘었어요」로 적습니다. 기록이 지워지면 넘긴 책이 바뀔 수 있습니다(매번 다시 셈).
- **무대**: 폭이 축척을 정하고 높이는 내용만큼(240~520px). 이번 주 괄호·이름표가 이정표에 닿으면 산과 이정표 사이를 벌리고, 목표 이름이 말풍선·꼭대기 높이와 부딪히면 점선 아래로, 깃발 이름은 눈금자·다른 글자와 부딪히면 적지 않습니다. 화면에 들어올 때 한 번 산이 솟습니다(동작 줄이기면 없음). 하늘에는 같은 연필로 그린 구름(손으로 설계한 세 가지, 그라데이션·흐림 없음)이 천천히 흘러갑니다. 이정표·말풍선·글자와 겹치지 않는 자리에만 띄우고 자리가 없으면 뺍니다. 폰은 위를 말풍선이 차지해 구름 몫의 하늘(36px)을 따로 둡니다. 위치는 고정 시드라 다시 그려도 제자리입니다. 유채색은 지층 외에 최근 올린 책 색 한 곳(꼭대기 깃발·이정표 그림)입니다.
- **HTML과 무대**: 높이·권수·막 올라온 책·지나온 이정표는 서버 HTML에 들어가고(시드 쿼리), 무대는 폭을 잰 뒤 브라우저에서 그립니다(`next/dynamic`, `ssr: false`). ISR HTML이 몇 시간 묵으므로 상대 시각(「5시간 전」)은 `suppressHydrationWarning`으로 브라우저 값을 쓰고, 넘은 날은 한국 시간으로 고정해 서버·브라우저가 같은 글자를 냅니다.
- **내 몫** (2026-10-01): 「내 책도 올리기」 바로 위에 「내가 쌓은 높이 24.8cm · 전체의 6.9%」. 버튼과 짝을 이뤄 더 올릴 이유를 주려는 자리이고, 상단 숫자 줄은 「다 같이」의 자리라 피했습니다. 높이를 크게, 비율은 뒤에 작게 둡니다(사용자가 적어 대부분 몇 %대). 0.1% 미만이면 「0.1% 미만」. 로그인했을 때만 `useMyMountainShareQuery`(`GET /reading-logs/mountain/me`)를 켜고, 비로그인이거나 산에 내 책이 없으면(비공개 설정 포함) 줄 자체를 그리지 않습니다. 브라우저에서만 받으므로 ISR HTML에는 들어가지 않습니다.
- **갱신**: 기록 뮤테이션이 `readingLogKeys._def`를 무효화하므로 기록하면 책동산과 내 몫도 다시 받습니다. 쿼리 staleTime 1분.
- 확인: Storybook `Feature/Lounge/LoungeMountain`(지금 규모·첨성대 앞·막 시작, 폰/데스크톱, 내 몫 있음·0.1% 미만·비공개), `pnpm vitest run src/features/reading-log`.
- **아직 없는 것**: 기록 토스트의 책동산 한 줄, 책동산 공유 이미지, 홈 위젯의 미니 책동산.

### 라운지 검색 노출 (2026-09-19)

- 라운지 페이지 RSC가 인기 도서·활성 독자와 함께 `readingLog.loungeFeed`의 첫 페이지를 시딩합니다. 최신 피드는 필수 쿼리로 지정해 장애 시 빈 HTML이 ISR에 저장되지 않게 합니다.

- 공개 목록 페이지는 빌드 시 사전 생성을 생략하고 첫 요청부터 ISR을 생성합니다. API 없는 CI에서도 빌드할 수 있고, 운영 조회 실패는 정상 캐시를 빈 목록으로 덮어쓰지 않습니다.
