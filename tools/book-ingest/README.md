# book-ingest — 신간 적재 도구

운영자가 로컬에서 원하는 출판사와 책을 골라 적재합니다. 카카오 API로 후보를 찾고,
DB에 없는 선택 도서만 **알라딘 웹에서 서지·표지·긴 소개·판형을, YES24에서 두께를**
받아 표지를 R2에 올린 뒤 `books`·`book_dimensions`에 넣습니다. 서버·웹 런타임에는
외부 도서 공급처를 추가하지 않습니다.

2026-11-01에 종료된 알라딘 Open API 공급처와 판형 대여 호출을 제거했습니다.
`ALADIN_TTB_KEY`가 환경에 남아 있어도 사용하지 않습니다. 배경은
[마이그레이션 계획서 6-e](../../docs/book-data-migration-plan.md#6-e-api-종료-후-신규-적재-개편-조사-2026-11-01),
필드 조사·사이트 이용 조건은 [가능성 조사](../../docs/aladin-site-ingest-feasibility.md)를 참고하세요.

## 수집 범위

- **출판사 신간:** 기본 최근 90일·출판사별 2페이지(페이지당 50건), 선택 출판사 전체에서
  **신규 후보 최대 30권**입니다. 기간·페이지·권수는 화면과 CLI에서 변경합니다.
- **책 검색:** 제목·저자·ISBN 검색. 기본 1페이지·신규 최대 30권이며 날짜 제한은 없습니다.
  CLI 적재에는 `--isbn`으로 선택한 ISBN이 필요합니다.
- **한 번에 최대 100권**입니다. 큰 범위는 출판사·기간을 나눠 실행합니다.
- **보유 ISBN은 상세를 받기 전에 제외**합니다. ISBN-10으로만 저장된 책도 보유로 봅니다.
- **과거 베스트셀러 대량 수집은 제공하지 않습니다.** 종료된 API 목록 모드는 화면에서 숨깁니다.
- 상한에 도달하면 그 사실을 결과에 표시합니다. 전체 목록을 확인했다는 의미가 아닙니다.
  신규 상한은 보유·제외 책을 세지 않으며 선택 출판사 순서대로 적용합니다.
- 후보 목록은 카카오가 제공하는 범위입니다. 출판사의 신간 전체를 보장하지 않습니다.
  빠진 책은 ISBN 검색으로 확인할 수 있습니다.

화면의 출판사 즐겨찾기·결과 거르기·상세·선택 기능은 유지합니다. 선택 중 숨겨진 책은
적재하지 않습니다. 출판사 조회 결과는 기본 선택, 자유 검색 결과는 기본 미선택입니다.
카드에서 보이는 서지·소개·표지는 아직 카카오 후보 정보이며 **알라딘·YES24 보강은 적재할 때만** 합니다.

## 저장 필드와 검증

| 필드 | 공급처 / 규칙 |
| --- | --- |
| ISBN·제목·저자·출판사·출간일 | 알라딘 웹. 요청 ISBN과 실제 ISBN, 후보 출판사 일치 확인 |
| 저자 | 이름 링크 뒤의 역할별로 분리해 역자는 제외. 이름 안 괄호·쉼표는 보존하며 그림·엮은이 등은 기존과 같이 저자에 포함 |
| `discount` | 알라딘 **정가**. 구조화 데이터의 판매가를 쓰지 않음 |
| `description` | 출판사 소개 전문 우선, 없으면 알라딘 소개 전문. 광고·요약·접기 버튼 제외 |
| `salesPoint` | 알라딘 판매지수. 0은 유효하며 결측과 구분. 적재 시점 스냅샷 |
| 표지 | 상품 페이지가 명시한 `cover500`. 실제 폭 500px 이상 확인 |
| 폭·높이·쪽수·무게·제본 | 알라딘 웹. 종이책 `bookFormat`과 기본정보를 사용 |
| **두께** | **동일 ISBN의 YES24 품목정보에서 3번째 mm 값만 사용** |
| 표지색 | 원본 표지에서 기존 k-means 알고리즘으로 추출 |

필수 서지·정가·출간일·판매지수·소개·판형 6개 항목·표지·표지색 중 하나라도 확보하지
못하면 해당 책은 **실패**로 남깁니다. NULL·기본값·추정 두께로 성공 처리하지 않습니다.
판형은 기존 `toDimensions`와 core `BOOK_SIZE_PLAUSIBLE` 범위를 적용하고 추정값은 저장하지 않습니다.

두께가 예전 알라딘 API 값과 달라도 YES24 값을 채택합니다(사용자 결정). 무게·가로·세로까지
YES24 값으로 바꾸지 않습니다. 기존 DB 행도 덮어쓰지 않습니다.

카카오 후보 단계의 공통 제외 규칙은 유지합니다: 출판사 불일치·제목/ISBN/정가/원본 표지 없음,
세트·ISSN 잡지·978/979가 아닌 바코드·전자책/비매품(`sale_price=-1`)·판매 상태 없음.
알라딘 보강에서도 ISBN·출판사·종이책 제본·세트 여부를 재확인합니다. 예약판매는 포함합니다.

## 처리 순서

```text
출판사·기간·권수 또는 검색어 선택
 → 카카오 후보 검색 → 정제·기간 제외 → DB 보유 ISBN 제외
 → 운영자가 적재할 책 선택
 → 쓰기 권한 점검 → 전체 실행 계획을 JSONL 기록
 → 한 권씩 알라딘 서지·소개 + YES24 ISBN 검색·상품 두께 확인
 → 전 필드 검사 → 표지 다운로드·가공 → R2 업로드·공개 URL 확인
 → 표지색 추출 → 한 트랜잭션으로 books·book_dimensions INSERT
```

- **R2 먼저, DB 나중**입니다. DB에는 `cdn.bookjeok.com` 자사 URL만 넣습니다.
- 기존 R2 키는 덮어쓰지 않고 재사용합니다(`immutable`).
- DB에는 SELECT·INSERT만 하며 UPDATE·DELETE·DDL은 없습니다.
- 두 테이블은 `ON CONFLICT DO NOTHING`입니다. 기존 판형 행의 NULL을 후속 보강하는 도구는 아닙니다.
- `scan`·보유 조회·권한 점검의 SELECT는 명시적 **READ ONLY 트랜잭션**으로 실행합니다.
- 표지는 기존 7-e 스펙을 유지합니다: WebP q85, PSNR 30dB 미만이거나 용량이 커지면 원본 유지.

## 속도·캐시·재시도

- 웹 HTML 요청은 **호스트별 직렬 처리·최소 3초 간격**입니다. 다른 봇 이름을 사칭하지 않습니다.
  이는 구현한 간격이며 사이트가 허용한 호출량을 뜻하지 않습니다.
- 검증에 성공한 상세·소개·YES24 검색·두께 페이지를 `.data/web-cache`에 **24시간** 보관합니다.
  재시도 시 유효한 성공 페이지는 다시 받지 않습니다. 빈 응답·오매칭·두께 누락은 성공 캐시하지 않습니다.
- 403·429·로그인 리다이렉트·접근 확인 화면·네트워크 연결 실패는 전체 적재를 중단합니다.
  HTTP 200 이후 본문을 받다가 연결이 끊기거나 시간 초과가 발생해도 동일하게 중단합니다.
  5xx는 간격을 두고 1회만 재요청하고 계속 실패하면 중단합니다. 차단 우회는 하지 않습니다.
- 필드 누락 등 한 책의 문제는 실패로 남기고 다음 책을 처리합니다.
- 화면에서는 **「실패한 책만 선택」 → 적재**로 재시도합니다. 미처리 책도 선택한 채 남습니다.
- 프로세스를 종료했다면 `retry --run <apply.jsonl>`로 실패·미처리 책을 복원합니다.
  기록상 성공한 책과 그 사이 DB에 들어간 책은 제외합니다. 같은 기록으로 재시도할 때도
  현재 DB를 대조하므로 이미 넣은 책의 상세를 다시 받지 않습니다.

**2026-11-01 실 코드 검증:** 출판사 3곳의 도서 5권(실제 검색에서 발견한 DB 미보유 신간 2권 포함)에
서지·소개·판형·두께·표지·표지색을 확보했습니다. 처음 확인은 권당 약 7.5~9.4초,
동일 책의 캐시 재확인은 약 0.45초였습니다. `inspect` 측정이라 R2·DB 쓰기 시간은 포함하지 않습니다.
30권은 웹 보강·표지 처리만 단순 환산하면 약 4~5분이고, 업로드·저장·추가 호출·실패에 따라 늘어납니다.
전체 도서의 성공률 또는 보장 시간은 아닙니다.

## 준비

1. 루트에서 `pnpm install` (Node 22).
2. `packages/core`가 빌드돼 있어야 합니다. 이 도구 변경으로 core 재빌드는 필요하지 않습니다.
3. `tools/book-ingest/.env.example`을 `.env`로 복사해 채웁니다. 같은 이름이 없으면 루트 `.env`를 읽습니다.

| 변수 | 용도 |
| --- | --- |
| `KAKAO_REST_API_KEY` | 후보 검색 (`scan`·화면·검색 후 `apply`) |
| `INGEST_DATABASE_URL` | DB 조회·적재. 전용 `book_ingest` 역할 권장 |
| `R2_ACCOUNT_ID`·`R2_ACCESS_KEY_ID`·`R2_SECRET_ACCESS_KEY` | 적재 때만 필요 |
| `R2_BUCKET` | 기본 `bookjeok-covers` |
| `INGEST_CDN_BASE` | 기본 `https://cdn.bookjeok.com` |

`inspect`는 DB·R2·카카오 키가 필요 없습니다. 알라딘 API 키도 어느 명령에서든 사용하지 않습니다.
새 환경 변수는 추가하지 않았습니다. DB 역할은 `books`·`book_dimensions` SELECT·INSERT 및 RLS 정책이
필요합니다([DDL 로그 9·12절](../../docs/manual-ddl-log.md)). 권한이 없으면 적재 시작 전 멈춥니다.

## 실행

저장소 루트에서:

```bash
# 출판사 선택 화면 (127.0.0.1:4700)
pnpm ingest serve

# 최근 90일·출판사별 2페이지·전체 신규 최대 30권, 쓰기 없음
pnpm ingest scan --publishers 민음사,창비

# 명시적인 범위
pnpm ingest scan --publishers 민음사 --since 2026-10-01 --max-pages 1 --max-books 10

# 검색 후 선택한 ISBN만 적재
pnpm ingest scan --query 9788937449741
pnpm ingest apply --query 9788937449741 --isbn 9788937449741 --yes

# 출판사 범위의 신규 후보 적재 (--yes 없으면 목록만)
pnpm ingest apply --publishers 민음사 --max-books 10 --yes

# DB/R2 쓰기 없이 웹 수집·500px 표지·색까지 검증 (최대 5권)
pnpm ingest inspect --isbn 9788937449673

# 중단한 실행의 실패·미처리 책만 이어서 (새 버전 기록만 지원)
pnpm ingest retry --run tools/book-ingest/.data/runs/시각-apply.jsonl
pnpm ingest retry --run tools/book-ingest/.data/runs/시각-apply.jsonl --yes
```

화면은 Host 헤더 검사·실행별 토큰·CORS 미허용으로 localhost 외부 요청을 차단합니다.
`--yes`와 화면의 적재 확인은 실제 운영 쓰기를 수행하므로, 먼저 `inspect`·`scan`으로 확인하세요.

## 산출물 — `.data/` (gitignore)

| 경로 | 내용 |
| --- | --- |
| `runs/*-scan.jsonl` | 후보 판정·제외 사유·카카오 원본·요약 |
| `runs/*-apply.jsonl` | 전체 실행 계획·성공/실패·보강된 서지와 출처·판형·표지 보고서. 재시도 입력 |
| `web-cache/` | 검증된 웹 응답과 수집 시각, 24시간 TTL. 지워도 재수집 가능 |
| `originals/` | 기존 표지 원본 보관 |
| `favorites.json` | 즐겨찾기 출판사 |
| `list-cache/` | 과거 알라딘 API 목록 캐시. 현재 사용하지 않음, 기존 실행 기록과 함께 보존 가능 |

웹 HTML 원본과 소개 전문은 `.data/` 밖의 테스트 fixture나 공개 저장소에 복제하지 않습니다.
테스트는 필요한 DOM 구조만 남긴 가상 문서를 사용합니다.

## 검증

```bash
pnpm --filter @bookjeok/book-ingest typecheck
pnpm --filter @bookjeok/book-ingest lint
pnpm --filter @bookjeok/book-ingest test --maxWorkers=1 --no-file-parallelism
```

외부 응답·DB·R2는 테스트 대역으로 검증하고 표지 가공·표지색은 실제 `sharp`를 사용합니다.
웹 파서는 실제 HTML로 별도 읽기 검증했고, 운영 DB 후보 검색도 READ ONLY로 확인했습니다.
**이번 개편에서 실제 운영 INSERT·R2 업로드는 실행하지 않았습니다.** DB 쓰기 스키마·권한은
바꾸지 않았고 기존 두 테이블 트랜잭션 코드를 재사용합니다. 사이트 구조가 바뀌면 파서 점검이 필요합니다.
2026-11-02 보완 후 타입 검사·린트·테스트 149개가 통과했습니다(단일 워커, 로컬 Node 24.15.0).
이름 안 괄호·쉼표와 역할 분리, 본문 수신 오류 시 전체 중단·미저장 회귀 검증을 포함합니다.
프로젝트 권장 Node 22에서의 실행은 이번 세션에서 별도로 확인하지 않았습니다.
